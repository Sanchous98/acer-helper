# Карта контекстов и словарь

Документ фиксирует **слова, которыми в проекте называют вещи**, и то, где каждая вещь обязана жить.
Он не переименовывает типы: переименование без словаря — это churn по дереву, где инвариант «фичи не
меняются». Словарь нужен там, где одно слово сегодня значит разное, а разные слова — одно и то же.

**Проверяется машиной.** Первая колонка таблицы ниже — имя **существующего типа**; тест
`tests/AcerHelper.Tests/GlossaryTests.cs` читает этот файл и проверяет, что каждое имя резолвится в сборке.
Поэтому словарь не может сгнить: переименованный или удалённый тип красит набор. Вторая и третья
таблицы содержат слова **без типа**, и их первая колонка намеренно не в бэктиках — резолвить там нечего.

---

## 1. Типы

| Тип | Что значит | Слой |
|---|---|---|
| `PerformanceProfile` | Намерение пользователя: `Id` (непрозрачный ключ бэкенда), `DisplayName`, `Kind`, цвета. **Не** аппаратный конверт мощности | Domain |
| `ProfileKind` | Грубый класс профиля. Управляет цветом иконки и семантикой «переключить производительность» | Domain |
| `ModeKey` | Идентичность режима, под которой лежат пресеты. Домен выводит её из одного профиля (`For` — пресеты режима лежат под тем, в который переключились); флаг Turbo и слот источника добавляет слой, владеющий свитчем (`LaptopService.ModeKeyFor`). **Не валидирует**, что названный профиль существует | Domain |
| `ModeAxis` | Ось, у которой есть пресет на режим: кулеры, GPU-офсеты, CPU power, Curve Optimizer, подсветка | Domain |
| `ModeAxisTable` | Пять осей как **данные**: политика «пресета нет», волатильность, кто переприменяет | Domain |
| `EmptyAxisPolicy` | Что делать, когда у текущего режима нет пресета: оставить / выставить сток / унаследовать вид | Domain |
| `ReassertOwner` | Кто переприменяет ось после того, как платформа её забыла: железо или UI | Domain |
| `OffsetCounts` | Смещение Curve Optimizer в AVFS-«counts». Овервольт этим типом **непредставим** | Domain |
| `Settings` | Граф настроек: `*Presets` по осям, слоты источников, скаляры. DTO хранилища | Domain |
| `ProfileMemory` | Режим, запомненный за источником питания: база + флаг Turbo | Domain |
| `FanPreset` | Пресет кулеров одного режима: режим + фиксированные скорости + две кривые | Domain — форма хранения, по разметке Infrastructure; **домен её больше не читает** (с 2026-09-17), переезд ожидает шага 4 |
| `GpuOcPreset` | GPU-офсеты одного режима, МГц (0 = сток) | Domain |
| `CoPreset` | Смещения Curve Optimizer одного режима, по рельсам | Domain |
| `LightPreset` | Подсветка одного режима, по зонам | Domain |
| `LightSettings` | Состояние одной зоны: эффект, яркость, скорость, цвет | Domain |
| `FanMode` | Поведение вентилятора: Auto / Max / Custom | Domain |
| `Fan` | Один вентилятор: свои данные (своя кривая или свой фиксированный ход) и последнее применённое к нему дежурство. **Кто он — не его дело**: флага CPU/GPU у модели нет, свою половину пресета выбирает вызывающий | Domain |
| `FanSettings` | Данные одного вентилятора, которыми снабжает его вызывающий: кривая, идти ли по ней или держать фиксированный ход, и сам фиксированный ход. Идентичности вентилятора в типе нет | Domain |
| `FanCurveEngine` | Пара вентиляторов и **парный** дедбенд: решает, писать ли вообще, и отдаёт обе скорости. Кривая, интерполяция и дежурство — в `Fan`; данные каждого вентилятора приходят с каждым `Step` | Domain |
| `SensorSnapshot` | Живая телеметрия температур и оборотов | Domain |
| `BatteryInfoSnapshot` | Живая телеметрия батареи | Domain |
| `AccentColor` | Нейтральный RGB-триплет без зависимости от тулкита | Domain |
| `ChoiceOption` | Один именованный вариант в списке, выбранный вендором | Domain |
| `RgbZone` | Зона подсветки: идентичность (`Name`), лампы, способы записи, «следует за профилем» | Domain |
| `VoltageDomain` | Независимо настраиваемый рельс напряжения: `Label` для показа, `Key` для хранения | Domain |
| `IDevice` | Подключённый ноутбук. Возможности — nullable-порты: `null` = фичи нет. Батарея — исключение: один объект `Battery`, который объявляет свои свойства сам | Domain |
| `Battery` | Батарея этой машины: телеметрия и каждое из зарядных свойств по отдельности (`null` = свойства нет) | Domain |
| `ISettingsStore` | Портируемое хранилище графа настроек | Domain |

## 2. Пять каналов «профиля» — самое опасное место словаря

Одно слово стоит перед пятью аппаратными реальностями, и **ни одно из вендорских понятий не получает
типа в Domain**: это была бы протечка ACL. Смежные понятия уже рассечены и закреплены тестом
`TheEcUsageModeIsNotTheProfileByte`.

| Слово | Что это на самом деле | Где |
|---|---|---|
| намерение пользователя | какой режим выбрал человек; несёт `PerformanceProfile` | Domain |
| индикатор прошивки | **значение** байта misc-setting 0x0B, `0x00`–`0x06`. Само `0x0B` — **индекс**, а не значение | `Infrastructure/Vendors/Acer/AcerProfiles.cs` |
| EC usage mode | то, что реально двигает конверт мощности. Достигается только по HID и ходит **противоположно** индикатору: Turbo — это байт 0x05, но usage mode 0 | `EneHidController`, `AcerEcHidController.ModeFor` |
| platform_profile | токен ядра/PPD на Linux: `balanced`, `low-power` | `Infrastructure/Vendors/Generic/PowerProfiles.Linux.cs` |
| power overlay | GUID слайдера ОС (Best efficiency / Balanced / Best performance) | `Infrastructure/Vendors/Generic/OverlayCpuPower.Windows.cs` |

**Запрещено** говорить «профиль» о чём-либо, кроме первого и четвёртого. Про каналы 2, 3 и 5 говорить
«индикатор», «EC usage mode» и «power overlay».

## 3. Слова без типа

| Слово | Значение | Почему без типа |
|---|---|---|
| триггер | Причина, по которой оси переприменяются: `Startup`, `ModeChanged`, `Resume`. Два из трёх — сброс состояния **платформы**, а не изменение модели | Доменного события смены режима нет и быть не может: домен про power-cycle не знает |
| каденция | Тайминг повторных попыток подсветки (400 мс × 8). Политика про руку пользователя и шину, не про железо | Живёт в UI намеренно |
| режим (без уточнения) | Запрещено. Говорить `ModeKey` (пресеты), `FanMode` (кулеры), EC usage mode или power overlay | Четыре разных понятия |

## 4. Граница, которую держит тест

`tests/AcerHelper.Tests/ArchitectureMapTests.cs` проверяет раскладку: namespace = папка, `*.Windows.cs` /
`*.Linux.cs` только под `Infrastructure/`, `Domain` не смотрит вверх. Единственное исключение —
`Domain/Settings.cs` тянет `Localization` ради `AppLanguage`, и оно названо, а не умолчано.
